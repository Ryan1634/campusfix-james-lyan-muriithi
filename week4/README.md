
# CampusFIX – Week 4: Use Case Model

This folder contains the use case model for CampusFIX. It shows how students, staff, maintenance workers and administrators interact with the system when reporting and following up facilities problems.

## Use Case Model

The diagram illustrates the main activities supported by CampusFIX, from submitting a maintenance request to assigning workers, updating progress and closing completed requests.

## What I learned

Working on the use case model helped me understand how different people interact with the system. I realised that reporting a problem is only the first step. The request must also be reviewed, prioritised and assigned before maintenance work can begin.

I also learned the importance of giving each user the right permissions and keeping a history of changes made to maintenance requests.

## Changes made after modelling

- Clarified the responsibilities of each system actor.
- Included login and logout activities.
- Added searching and filtering of requests.
- Included the maintenance dashboard.
- Clarified the request lifecycle: Submitted, Assigned, In Progress, Resolved and Closed.
